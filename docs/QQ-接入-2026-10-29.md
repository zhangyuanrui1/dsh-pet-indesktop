## 步骤 1 · 装插件 dsh-plugin-qq-bridge

### 方式 A：一行命令（推荐）

在**终端**（不是 DSH 对话框）里执行：

```bash
npx --yes dsh-plugin-qq-bridge@latest install
```

它会自动：找到 `desktop` profile → 安装包 → 写进 `dsh.profile.bundles` → 提示重启 DSH。
每次写文件都带快照，任一步失败会**整体回滚**。

**如果报这个错**（我这台机器上遇到了）：

```
[EPERM] EPERM: operation not permitted, unlink
'C:\Users\Admin\.pnpm\store\v11\projects\11f96c0b76518639a7538bdcebffcfc8'
```

说明 pnpm 全局 store 里有个目录被占用/锁死了。按顺序试：

1. **先关掉所有 node 进程**（包括 DSH、桌宠），再重跑上面的命令。
2. 还不行就把那个目录删掉（它是 pnpm 的"项目登记"目录，删了 pnpm 会重建，不影响已装的包）：
   ```powershell
   Remove-Item 'C:\Users\Admin\.pnpm\store\v11\projects\11f96c0b76518639a7538bdcebffcfc8' -Recurse -Force
   ```
   然后重跑安装命令。
3. 仍然失败 → 直接走方式 B，别在 pnpm 上耗。

### 方式 B：在 DSH 界面里装（绕过 pnpm 报错）

左侧 **插件** 页 → **安装 bundle** → target 填包名：

```
dsh-plugin-qq-bridge
```

> 注意：DSH 里的 `plugin_manager` 是**内部工具**，只在对话框里对 Agent 说"装一下 dsh-plugin-qq-bridge"才会被调用，在终端里敲它是无效命令。

### 方式 C：npm 装到本地再指路径（B 失败时用）

```bash
npm i dsh-plugin-qq-bridge
```

然后在插件页安装 bundle 时，target 填 `node_modules\dsh-plugin-qq-bridge` 的**绝对路径**。

### 装完必须做

**重启一次 DSH**（Host 半边不热替换）。重启后，每条 DSH 会话的输入框下方会出现一行 `QQ …`。

## 步骤 2 · 装 SnowLuma 并登录小号

1. 打开 GitHub Releases：`https://github.com/SnowLuma/SnowLuma/releases/latest`
2. 下载 **`SnowLuma-v2.2.1-win-x64.zip`**（41MB，完整版，自带运行时；`-lite` 只有 7MB，需要你自己有 Node 环境，不推荐）
3. 解压到一个**路径不含中文和空格**的目录，例如 `D:\SnowLuma`
4. 双击 **`launcher.bat`**
5. 浏览器打开 **`http://localhost:5099`**
6. 登录密码在**启动日志里**（那个黑窗口里找），首次登录后建议改掉
7. 同意 EULA → 按引导**接入 QQ 进程** → **扫码登录小号**

> SnowLuma 需要 QQ 客户端窗口在跑（这点和 NapCat 不同）。登录态不在安装目录，换机器要重新扫码。

## 步骤 3 · 在 SnowLuma 里开 OneBot 的 WebSocket 服务端

WebUI → **连接配置**（或"网络配置"）→ 新建 → 类型选 **WebSocket 服务端**：

| 配置项 | 填什么 | 说明 |
|---|---|---|
| 监听地址 / Host | `127.0.0.1` | 只在本机回环，别开公网 |
| 端口 | `3001` | OneBot WS 默认口。**3000 是 HTTP API，5099 是 WebUI，别搞混** |
| **消息格式** | **`array`** | 最容易漏的一项，选成 string 会多一层 CQ 转义 |
| **Access Token** | 自己定一段串，例如 `dafeiyu-2026` | 记下来，下一步要填进 DSH 面板 |
| 心跳 | 30000 | 保持默认 |
| 上报自身消息 | 关闭 | 没意义 |

保存（SnowLuma 的 WebUI 改配置**即时生效**，不用重启）。

> **两个 token 不是一回事**：WebUI 的登录密码 ≠ OneBot 的 Access Token。要填进 DSH 的是**后者**。
> 如果 SnowLuma 的 HTTP 和 WS 各有一个 token，面板里的"HTTP token"栏留空就会沿用 WS 那个。

**验证**：SnowLuma 这一侧此时应该显示 `3001` 在监听；Windows 上可以 `netstat -ano | findstr 3001` 看一眼。

## 步骤 4 · 在 DSH 里配置插件

1. **先开一条会话**（插件是**按会话**关联联系人的：会话 A 可以接私聊，会话 B 接群，互不影响）
2. 会话输入框下方会出现一行 **`QQ …`**，点开，分两块填：

**① QQ 连接**

| 字段 | 填什么 |
|---|---|
| OneBot 正向 WS 地址 | `ws://127.0.0.1:3001/` |
| Access Token | 步骤 3 你定的那串 |
| HTTP API 地址（可选） | `http://127.0.0.1:3000/`，WS 断了时兜底发消息 |
| 机器人 QQ 号 | 小号的 QQ 号 |

点 **【测试连接】**——它会调 `get_login_info`，能返回小号昵称就说明通了；再点【保存并连接】。

**② 本会话关联的联系人**

- 选 **私聊** 或 **群聊**
- 填号码（或点 **「从 QQ 拉取列表」** 从好友/群列表里直接选）
- 点 **【关联到本会话】**
- 群聊会多一个 **「仅被@时才回复」** 开关，**默认开启**，建议保持

## 常见坑（按踩坑概率排序）

1. **一条 OneBot WS 只能被一个客户端占用**——别同时装 `dsh-onebot-qq` 和 `dsh-plugin-qq-bridge`，会各收一半消息
2. **消息格式忘了选 `array`**——最常见，表现为解析异常/多一层转义
3. **token 填成 WebUI 密码**——表现为鉴权失败或连上就断
4. **装完没重启 DSH**——面板不会出现 `QQ …` 那一行
5. **QQ 自动升级**——升级后可能超出协议端支持范围，表现为收不到上报；建议关掉 QQ 自动更新
6. **杀软隔离**——SnowLuma/NapCat 这类 hook 型工具容易被拦，确认关键 exe/dll 还在
7. **端口被占**——3001 被别的东西占了会直接起不来；`netstat -ano | findstr 3001` 查

## 桌宠这边会发生什么

- `dsh-pet` 监听的是 DSH 的整体 Agent 活动：QQ 来消息 → 鱼进入忙碌 → 回合结束 → 完成动作
- **回复正文在 QQ 里**（超过 150 字会被插件渲染成文字卡）；桌宠的 TTS **不会**朗读它
- 想让人设一致：QQ 会话挂载的 workspace 里放一份 `AGENTS.md`，把大肥鱼的人设要点写进去（或直接用 DSH 的预设），否则 QQ 里那条会话用的是通用人设，和桌宠的鱼不是同一张嘴

## 追加 · 托盘启动 DSH 吞错修复 + 常驻看护（2026-10-29 傍晚）

### 问题回顾

QQ 联调时踩到的坑正式修掉：托盘「启动 dsh web 界面」过去把 dsh 子进程的
stdout/stderr 全进 DEVNULL——dsh 启动失败（凭据文件写坏、插件栈崩、端口
冲突等）**全程静默**，桌宠气泡一直说「正在后台启动……」而端口永远起不来，
错误无处可查。当天 `.credentials.yaml` 被 DUPLICATE_KEY 卡死那次就是这样
排查了半天的。

### 修复内容（pet/harness_launcher.py + pet/app.py）

1. **输出落盘**：每次 spawn 的子进程输出写到
   `%APPDATA%\dsh-pet-standalone\logs\dsh-web-YYYYMMDD-HHMMSS.log`
   （按次分文件，只保留最近 5 份）。日志开不出来不影响启动（退回 DEVNULL）。
2. **早退气泡**：spawn 后挂退出监视线程，dsh 进程死亡（且不是被主动终止的）
   时桌宠弹气泡「dsh web 进程已退出（可能启动失败）。日志：<路径>」。
   「启动后干等 90 秒毫无下文」的观感同步消除——进程死了等待线程立即放弃。
3. **常驻看护（supervisor）**：随桌宠常驻的单例 daemon 线程（10s 一轮），
   只看**自拉起的** dsh web：
   - 意外退出且功能门满足（DSH 联动开 + harness 自启开 + 非退出/会话结束）
     时自动重启（headless service 目标，不开界面）；
   - 重启失败按退避翻倍（20s 起、上限 5 分钟），进程活着即清零；
   - 端口有人监听（用户自己的实例/别的 dsh）绝不重复拉起；
   - **用户主动停止闩**：托盘「停止服务」/ 联动关闭收口终止过实例后不再
     复活（不跟用户的明确决定对着干）；菜单显式启动一次即清闩。
4. **退出收口**：桌宠退出先停看护再收口自拉起实例，杜绝看护与退出赛跑。

### 排障入口

- 看日志：`%APPDATA%\dsh-pet-standalone\logs\dsh-web-*.log`（最新一份）
- 查端口：`netstat -ano | findstr 38080`
- 气泡事件三类：`exited`（进程退出）/ `supervisor-restarted`（已自动拉起）/
  `supervisor-failed`（自动重启失败，含原因）

  早退回报与主动终止抑制、看护 tick 全分支（alive/listening/gated/stopped/
  backoff/restarted/failed）、用户停止闩、看护线程生命周期。
- 回归：harness 四套件 + 托盘/菜单三套件共 258 例全绿（test_harness_launcher /
  ownership / lifecycle / background_service_gates / tray_icon_ready /
